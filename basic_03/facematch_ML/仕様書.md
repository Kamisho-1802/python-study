## 1. プロジェクト概要

- **目的**: スマホのカメラで撮影した顔と、事前に用意した有名人の顔を比較し、似ている上位3人を類似度付きで返す。
- **コア技術**: 顔を特徴ベクトル（embedding）に変換し、ベクトル空間上の距離で類似度を測る（= metric learning による顔認識の応用）。
- **やらないこと（non-goals）**:
  - 顔の「美しさ採点」はしない（客観的な正解が存在せず、バイアスの再生産になるため）。
  - モデルの自前学習はしない。学習済みモデルを使う。
  - 撮影画像の永続保存はしない（プライバシー要件、第11章）。

---

## 2. システム構成

2段階のパイプラインで作る。**①と②で必ず同じ埋め込みモデルを使うこと**（別モデルで作ったベクトルは比較できない）。

```
① 事前準備（オフライン・1回だけ実行）
  有名人画像 → 顔検出/整列 → 埋め込みモデル → ベクトルDB（FAISS index + ラベル）

② リクエスト時（オンライン・毎回実行）
  スマホ撮影 → 顔検出/整列 → 同じ埋め込みモデル → 最近傍探索（ベクトルDBを検索）→ 似てる有名人
```

## 6. フェーズ1 — 顔の埋め込みを理解する（ローカル）

### やること
`data/` に自分の顔写真2枚と、似ていそうな有名人の写真1枚を置き、`src/explore_embeddings.py` を作って動かす。

```python
from deepface import DeepFace

MODEL = "Facenet512"
DETECTOR = "retinaface"

# (1) 2枚の顔の類似度を確認する
result = DeepFace.verify(
    img1_path="data/me_1.jpg",
    img2_path="data/me_2.jpg",
    model_name=MODEL,
    detector_backend=DETECTOR,
)
print("distance:", result["distance"], "same person?:", result["verified"])

# (2) 生の埋め込みベクトルを取り出す
rep = DeepFace.represent(
    img_path="data/me_1.jpg",
    model_name=MODEL,
    detector_backend=DETECTOR,
)
print("ベクトルの次元数:", len(rep[0]["embedding"]))  # 512 になるはず
```

### 完了条件
- 同一人物の2枚で `distance` が小さく、別人だと大きくなることを目視で確認できる。
- 埋め込みの次元数が 512 と表示される。

### 学習メモ
- **埋め込み（embedding）**: 顔画像を 512 個の数値からなるベクトルに変換したもの。「同じ人は近く、別人は遠く」配置されるように学習済みモデルが作る。
- **距離と類似度**: `distance` が小さい = 似ている。後のフェーズでは「コサイン類似度（大きいほど似ている）」に統一する。
- `DeepFace.represent` は顔が複数写っているとベクトルを複数返す（リスト）。1人だけ写った写真を使うこと。

## 7. フェーズ2 — 有名人ベクトルDBを作る（インデックス作成）

### やること
1. 有名人画像を `data/celebs/<人物名>/*.jpg` の形で配置する。
   - **公開データセットを使う**（自前スクレイピングは著作権・肖像権のリスク）。例: VGGFace2、Kaggle の "Pins Face Recognition" など。ライセンス（研究用途限定か等）を必ず確認する。
   - まずは 50〜200 人、1人あたり数枚で十分。
2. `src/build_index.py` を作る。全画像を埋め込み化し、FAISS index とラベルを保存する。

```python
import os, json, numpy as np, faiss
from deepface import DeepFace

MODEL, DETECTOR = "Facenet512", "retinaface"
DATA_DIR, OUT_DIR = "data/celebs", "index"

vectors, labels = [], []
for name in sorted(os.listdir(DATA_DIR)):
    person_dir = os.path.join(DATA_DIR, name)
    if not os.path.isdir(person_dir):
        continue
    for fn in os.listdir(person_dir):
        path = os.path.join(person_dir, fn)
        try:
            reps = DeepFace.represent(path, model_name=MODEL, detector_backend=DETECTOR)
        except ValueError:
            print("顔を検出できずスキップ:", path)
            continue
        vectors.append(np.array(reps[0]["embedding"], dtype="float32"))
        labels.append(name)

mat = np.vstack(vectors).astype("float32")
faiss.normalize_L2(mat)                 # コサイン類似度のために L2 正規化
index = faiss.IndexFlatIP(mat.shape[1]) # 内積 = 正規化済みならコサイン類似度
index.add(mat)

os.makedirs(OUT_DIR, exist_ok=True)
faiss.write_index(index, os.path.join(OUT_DIR, "celebs.faiss"))
with open(os.path.join(OUT_DIR, "labels.json"), "w", encoding="utf-8") as f:
    json.dump(labels, f, ensure_ascii=False)
print("登録ベクトル数:", index.ntotal)
```

### 完了条件
- `index/celebs.faiss` と `index/labels.json` が生成される。
- `登録ベクトル数` が、用意した画像枚数（顔検出に失敗した分を除く）と一致する。

### 学習メモ
- **正規化 + 内積 = コサイン類似度**。`normalize_L2` でベクトルの長さを1にしてから内積を取ると、向きの近さ（コサイン類似度）になる。クエリ側も同じ正規化をすること。
- 同一人物の複数画像はそれぞれ別ベクトルとして登録してよい（検索時に複数ヒットしても、ラベルでまとめれば安定する）。

## 8. フェーズ3 — 検索ロジック + API（FastAPI）

### やること
1. `src/search.py` を作る。

```python
import json, numpy as np, faiss
from deepface import DeepFace

MODEL, DETECTOR = "Facenet512", "retinaface"
_index = faiss.read_index("index/celebs.faiss")
_labels = json.load(open("index/labels.json", encoding="utf-8"))

def find_lookalike(img_path: str, k: int = 3):
    reps = DeepFace.represent(img_path, model_name=MODEL, detector_backend=DETECTOR)
    if len(reps) == 0:
        return {"error": "顔が見つかりませんでした"}
    if len(reps) > 1:
        return {"error": "顔が複数写っています。1人で撮影してください"}
    q = np.array(reps[0]["embedding"], dtype="float32")[None, :]
    faiss.normalize_L2(q)
    sims, idx = _index.search(q, k)
    return [
        {"name": _labels[i], "similarity": round(float(s), 4)}
        for s, i in zip(sims[0], idx[0])
    ]
```

2. `src/main.py` を作る。撮影画像を受け取り、判定して JSON で返す。**画像はメモリ/一時ファイルで処理し、保存しない。**

```python
import tempfile, shutil
from fastapi import FastAPI, UploadFile, File
from fastapi.staticfiles import StaticFiles
from search import find_lookalike

app = FastAPI(title="Celebrity Lookalike")

@app.post("/analyze")
async def analyze(file: UploadFile = File(...)):
    with tempfile.NamedTemporaryFile(suffix=".jpg") as tmp:
        shutil.copyfileobj(file.file, tmp)
        tmp.flush()
        result = find_lookalike(tmp.name, k=3)   # with を抜けると一時ファイルは自動削除
    return {"matches": result}

# フェーズ4の web/ を配信する
app.mount("/", StaticFiles(directory="web", html=True), name="web")
```

3. 起動して確認する。
   ```bash
   uvicorn src.main:app --reload --port 8000
   ```
   ブラウザで `http://localhost:8000/docs`（FastAPI 自動ドキュメント）から `/analyze` をテストする。

### 完了条件
- `/docs` から自分の写真をアップロードすると、似ている有名人の名前と類似度が JSON で返る。
- 顔のない画像、複数人の画像でエラーメッセージが返る。

### 学習メモ
- **顔が検出できない/複数いるケースを必ず処理する。** これが本番で一番多いエラー。
- `--reload` は開発用（保存で自動再起動）。本番では付けない。

## 9. フェーズ4 — スマホ撮影フロント

### やること
`web/index.html` を作る。`getUserMedia` でカメラ映像を表示し、撮影ボタンで静止画を取得し、`/analyze` に POST して結果を表示する。

骨組み:
```html
<!DOCTYPE html>
<html lang="ja">
<body>
  <video id="cam" autoplay playsinline></video>
  <button id="shot">撮影して判定</button>
  <canvas id="canvas" hidden></canvas>
  <div id="result"></div>
  <script>
    const video = document.getElementById("cam");
    navigator.mediaDevices.getUserMedia({ video: { facingMode: "user" } })
      .then(s => video.srcObject = s);

    document.getElementById("shot").onclick = async () => {
      const canvas = document.getElementById("canvas");
      canvas.width = video.videoWidth;
      canvas.height = video.videoHeight;
      canvas.getContext("2d").drawImage(video, 0, 0);
      const blob = await new Promise(r => canvas.toBlob(r, "image/jpeg"));
      const fd = new FormData();
      fd.append("file", blob, "shot.jpg");
      const res = await fetch("/analyze", { method: "POST", body: fd });
      document.getElementById("result").textContent = JSON.stringify(await res.json());
    };
  </script>
</body>
</html>
```

### 完了条件
- スマホ/PCのブラウザでカメラが表示され、撮影で判定結果が画面に出る。
- 結果表示を整える（名前・類似度を見やすく）。

### 学習メモ
- **`getUserMedia` は HTTPS か `localhost` でしか動かない。** スマホ実機テストでは、PC の `localhost` ではなく HTTPS が必要（フェーズ5で対応）。
- `facingMode: "user"` で内側カメラ、`"environment"` で外側カメラ。

## 10. フェーズ5 — AWS デプロイ

> ここから課金が発生しうる。**各 AWS 操作は実行前に人間に確認する。鍵・パスワード・課金確定は人間が行う。**

### やること
1. **最初に予算アラートを設定**（AWS Budgets）。例: 月 $5 を超えたらメール通知。これを最優先で行う。
2. **S3 バケットを作成**し、`index/`（FAISS index と labels.json）をアップロードする。`data/celebs/` は容量が大きければ任意。
   ```bash
   aws s3 mb s3://<バケット名>
   aws s3 sync index/ s3://<バケット名>/index/
   ```
3. **EC2 インスタンスを起動**する。
   - インスタンスタイプ: `t3.medium` 以上を推奨（`deepface` はメモリを使うため、無料枠の `t2.micro` ではメモリ不足になりやすい。学習中はこまめに停止すること）。
   - OS: Ubuntu。
   - セキュリティグループ: 動作確認時のみアプリのポートを自分のIPに限定して開ける。常時公開しない。
4. **IAM ロール**を EC2 に付与し、S3 から `index/` を読めるようにする（アクセスキーをコードに書かない）。
5. EC2 上でセットアップして起動する。
   ```bash
   # 依存をインストール（フェーズ0と同じ requirements.txt）
   aws s3 sync s3://<バケット名>/index/ index/
   uvicorn src.main:app --host 0.0.0.0 --port 8000
   ```
6. **HTTPS 化**（スマホ実機で `getUserMedia` を使うため必須）。Nginx + Let's Encrypt（独自ドメイン）か、当面は開発用トンネル（例: `cloudflared` 等）で代用してよい。
7. 常駐させるなら `systemd` サービス化、または `gunicorn` + `uvicorn` ワーカーで起動する。

### 完了条件
- 予算アラートが設定済み。
- スマホ実機（HTTPS）でカメラ撮影 → 判定が通る。
- 使い終わったら EC2 を **停止または削除**して課金を止められる。

### 学習メモ
- **アクセスキーをコードや Git に絶対に置かない。** EC2 には IAM ロールで権限を渡す。
- 料金の大半は EC2 の起動時間と S3 保管料。**触っていない間は EC2 を停止**する習慣をつける。
- セキュリティグループで全開放（0.0.0.0/0）にしないこと。

## 14. 学習メモ（つまずきやすいポイント）

- **モデルを途中で変えない。** index 作成（フェーズ2）と検索（フェーズ3）で `MODEL` / `DETECTOR` が一致していないと、まともな結果が出ない。定数は1か所にまとめる。
- **正規化のし忘れ。** index 側だけ正規化してクエリ側を忘れると類似度がおかしくなる。両方 `normalize_L2` する。
- **`getUserMedia` が動かない**ときは HTTPS か localhost かを最初に疑う。
- **初回が遅い**のは `deepface` がモデルの重みをダウンロードしているため。2回目以降は速くなる。
- 仮想環境に入り忘れていないか（プロンプトの `(.venv)`）を常に確認する。

## 15. 発展課題（完成後に挑戦）

- 同一人物の複数ベクトルを平均して1人1ベクトルにまとめ、結果を安定させる。
- 類似度に閾値を設け、「該当なし」を返せるようにする。
- ベクトル検索を AWS OpenSearch の k-NN に置き換え、マネージドな構成にする。
- 埋め込みモデルを SageMaker エンドポイントにデプロイし、API から呼び出す。
- 埋め込みモデルを `Facenet512` から `ArcFace` に替えて精度を比較する（index を作り直すこと）。
